# P-031 — Restrict `derived_from` parents to Source/Memory/Action (FIX_PROMPT B4)

Status: spec (2026-10-16). Small item; lands in the same stretch as B1-B3.

## Problem (audit-verified)

`derived_from` accepts any existing node id, including `Session` and `Revocation` nodes,
which corrupts ancestry semantics (`blame`/`impact`/revoke discovery walk FEEDS meant to link
knowledge nodes). Today it fails late/obscurely (see P-021's char-iteration finding) instead of
being rejected up front.

## Fix plan

1. In the ingest validation path (engine/ingest.py parent check for `remember` and the
   `/v1/events` mapping), reject parents whose labels do not intersect
   `{Source, Memory, Action}` with `InvalidArgument` (`invalid_argument` -> HTTP 422,
   MCP `ok:false`): message like "parent must be Source, Memory or Action".
2. Same rule on the MCP tools that take `derived_from`.
3. No schema change.

## Tests first

- Table-driven: create a Session and a Revocation node; try `remember(derived_from=[...])` and
  `/v1/events` with those ids -> 422 `invalid_argument`, no partial write; valid parents
  (Source/Memory/Action) still accepted.
- MCP: `pedigree_remember` with a Session parent -> `ok:false` `invalid_argument`.

## Acceptance

- All rejections 422/`invalid_argument` (never 500); valid graphs unaffected; `make check` green.
