## Problem (verified in-tree 2026-10-16)

- `FALKOR_PORT=1 .venv/Scripts/python.exe -c "import pedigree.api.app, pedigree.mcp_server"`
  fails with `RuntimeError: index creation failed: ... refused` (registry `ensure_schema`
  runs at import). **Exact audit failure reproduced.**
- Causes: `src/pedigree/api/app.py` ends with `app = create_app()` (connects/indexes on import);
  `src/pedigree/mcp_server.py:243-257` runs `_build_default()` at import (creates a `Db`,
  pings, builds a full MCP server).
- `_build_default` / the module-level `mcp` global are **dead code**: nothing imports them
  (grep-verified; all callers use `build_mcp`). Delete both.
- `src/pedigree/cli.py:147` (`serve`) uses `uvicorn.run("pedigree.api.app:app", ...)` which
  depends on the module-level `app` — switch to factory form.

## Fix plan

1. `api/app.py`: delete the module-level `app = create_app()`.
2. `cli.py` serve: `uvicorn.run("pedigree.api.app:create_app", factory=True, host=..., port=...,
   log_level="info")`.
3. `mcp_server.py`: delete `mcp = None`, `_build_default()`, and its invocation.
4. Docs coherence sweep (includes a P-016 devex finding): `docs/09-TECH-CHEATSHEET.md` dead
   command -> `python -m pedigree.cli mcp --transport stdio`; update any `api.app:app`
   copy-paste strings in docs to `--factory pedigree.api.app:create_app`.
5. Container/entrypoint untouched: `scripts/entrypoint.sh` runs `pedigree.cli serve`
   (verified), which picks up the factory change.
