# P-020 — Correct rate limiting + O(1) auth (FIX_PROMPT C4)

Owner: Phase C. Status: implemented; independent QA/red-team and final root gate PASS.
Authoritative contract: [consult 012](../consults/012-p020-auth-rates/decision.md), ADR-013.

## Problem (verified)
- Writes count twice (60/min allowed while advertised 120/min, dogfood S20 measured 120x200).
- Reads share the write bucket.
- `registry.resolve` loops all tenants on a miss: 3ms -> 75ms at 307 tenants (P-013 `X-Admin-Token`
  no, agent-token lookup path).
- No failed-auth throttle (20 invalid tokens → ~422ms, no 429).

## Fix plan
1. Three nullable credential-slot indexes support one static digest OR lookup. Stored
   digest/status/prefix checks remain live; ambiguous candidates reject. The authority
   cache and tenant scan are removed. `invalidate_cache()` is a compatibility no-op.
   This is bounded indexed query work, not a mathematical constant-time DB claim.
2. Separate read/write buckets per tenant; counts match advertisement; reads never count against the
   write bucket.
3. Shared failed-auth backoff: ten unauthorized outcomes per peer, then reject before
   lookup with Retry-After until expiry. Actual transport peer only; shipped HTTP
   launch paths disable Uvicorn proxy-header rewriting. Stdio has one local scope.
4. Document per-process/per-instance limits (KNOWN_ISSUES / README).

## Tests first
- dogfood S20 informational expected count; new: exactly 120 writes allowed then 429.
- benchmark: 1000 tenants (synthetic), resolve unknown token < 10ms (measured in test, real numbers).
- failed-auth throttle (10x401 → next → 429).
- invalid token latency constant across sizes.

## Acceptance
- audit resolve loop gone; `registry.resolve` uses one indexed live lookup; tests pass.
- red-team F-2/F-3 and QA-3 feed here.

## Implemented accounting and evidence

One locked limiter instance is shared by REST and mounted MCP. Tenant budgets are
shared across agent/operator credentials. Read-only gate and GET/report/blame/audit
use reads; ingest/sessions/corroboration, recorded gate and what-if use writes.
Revoke/reinstate additionally reserve destructive-operation capacity; their dry runs
use reads plus that capacity. All applicable buckets reserve atomically; rejected
reservations consume none. Pre-admission validation/permission denials consume no
tenant capacity; admitted engine failures do. Each request/batch charges once.

State keys and sample deques are bounded. Expired keys are pruned; active saturation
fails closed rather than evicting an exhausted key into a fresh allowance. Limits
are per instance, independent across workers/restarts. Backoff can temporarily deny
a valid caller sharing a blocked peer/NAT. Outcome accounting does not bound all
concurrent authentication work already in flight. Custom proxy deployments must
establish an explicit trusted peer boundary; spoofed forwarding headers are not identity.

Actual RED: write admission stopped at request sixty under duplicate charges;
read exhaustion blocked a write. Registry misses used 32 / 1,002 queries and a label
scan before indexing; duplicate authority was admitted. MCP writes were unmetered.
Root launch test reproduced missing proxy_headers=False before repair.

Independent QA: 48 passed in 19.15s with ownership sentinel unchanged; see
[report](../qa/P-020.md). Real registry plans/counts, live process rotation/revocation,
TCP REST/MCP budgets and CLI stdio are separated from deterministic clock tests.
Local median miss probes at 31 / 1,001 synthetic rows: 0.726 / 0.773 ms; both use
one production query and indexed plans. These are local acceptance samples, not
production maximums or published evaluation numbers.

Final independent red-team: 13 passed in 4.25s; final security suite: 414 passed,
1 skipped, 1 xfailed in 125.30s with ownership sentinel unchanged. Root final
`make check`: 787 passed, 2 skipped, 3 deselected, 1 xfailed in 193.28s;
Ruff, tracked secrets and numbers PASS. The first root gate exposed an audit limit
compatibility regression. Restoring the existing integer clamp to 1..50 (without
changing its original tests) gave 47 focused passes before the full rerun.
Malformed noninteger audit limits still reject before read admission.
Dogfood: 22 PASS, 0 FAIL, 1 EXPECTED-FAIL, 0 STALE, 0 SKIP; only P-022 application
metrics remain expected-failing. Fresh-clone/push checkpoint recorded separately.
