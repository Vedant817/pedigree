## 2. Pinned semantics (the contract the oracle encodes) — R1/R2/R3

- **R1 · Reinstate.** `reinstate(r)`: `R := R \ {r}`, then recompute the **whole** status map from
  structure under the remaining root set. Nodes in `R` are never reset; a revoked root that is
  also a descendant of `r` stays `revoked` (root precedence). Descendants of `R` are recomputed;
  nodes outside `desc(R)` are `ok`.
- **R2 · Corroboration is lazy.** `corroborate(m, s)` adds the edge only; node statuses do not
  change until the next recompute (revoke/reinstate). Support is effective as of the last
  recompute. Making `corroborate` recompute is explicitly **out of scope** for P-012 (it would
  change a public behaviour and needs its own acceptance criteria; recorded in ADR-015).
- **R3 · "Healthy support".** A memory is `preserved` iff it has a bad parent and at least one
  `CORROBORATED_BY` source whose **status is `ok`**. `by` (agent/human/scanner) and `integrity`
  do not enter the status recurrence.
- **R4 · No `quarantined` output.** After a quiescent op no node may remain `quarantined`; the
  oracle never emits it, and a quarantined node in the graph is itself a divergence.
- **R5 · Marker lifecycle.** `revoked_at`/`reason` are cleared by `Q_REINSTATE_ROOT` for the
  reinstated root only. `Revocation` rows are audit history and persist across a legitimate
  reinstate, so the root set is driven by node status (`revoked_roots()`), never by rows.
- **R6 · No-op ops are in scope.** `revoke(already-revoked)` and `reinstate(never-revoked)` are
  no-ops that must leave the map unchanged; `reinstate(x)` models `R \ {x}` unconditionally.
- **R7 · Precedence.** (1) `r ∈ R ⇒ revoked` (root wins even as a descendant); (2) descendants not
  in `R`: any parent finally `revoked|tainted` ⇒ bad path → `preserved` if some support source
  ∉ `R`, else `tainted`; (3) nodes outside the descendant union ⇒ `ok`; (4) never emit
  `quarantined`. A `preserved` parent is **not** bad — its children can be `ok` (that is the
  feature; do not "fix" it).

   is unchanged. A no-op revoke/reinstate is not a recompute: the edge is folded at the next one.
   *Evidence:* `tests/integration/test_reinstate_oracle.py` (the driver asserts exactly this).

## 4. R8 decision (recorded as required)

Two independent oracles already existed: `evals/oracle.py` (brute-force fixpoint, guarded against
`engine/compute.py` by `tests/evals/test_oracle_agreement.py` on 1000 DAGs) and the brute force in
`tests/unit/test_compute.py`. The pre-existing `tests/oracle.py` was only a re-export shim of
`evals.oracle`, so it gave no independent code path.

**Choice:** `tests/oracle.py` becomes the third, independent implementation of the §3 pseudocode
(`global_fixpoint`), importing nothing from `pedigree` (enforced by an AST meta-test which also
forbids importing `evals`, a strictly stronger rule than the review asked for). Agreement with
`evals.oracle.ground_truth` is not assumed: a **drift guard** in `tests/unit/test_p012_oracle.py`
compares the two on that oracle's valid domain (single/full root set `R`, all statuses `ok` —
the caveat in R8, where a `statuses`-revoked node outside `R` is treated as `ok` by
`evals.oracle`, is deliberately not exercised). Extending `evals/oracle.py` with a global API was
rejected: it would put the P-012 driver's semantics into a file that E1's report and baselines
consume, and the drift guard gives the same protection without coupling.

## 5. Non-goals

- No engine change: P-012's product fix already landed; this work adds evidence machinery and
  specification text only. If the battery finds a real divergence, that is a **new** finding —
  report it, do not patch `engine/` under this spec.
- Concurrency/quarantine races (P-024) and multi-process runs are out of scope (no concurrent
  writer in this battery).
- `corroborate` gains no recompute (R2 alternative).
- `docs/PROGRESS.md` and `docs/DEVELOPMENT_HANDOFF.md` are owned by the orchestrator.
