# P-015 — Role separation: agent vs operator (FIX_PROMPT C1)

Owner: Phase C. Mandatory domain/architect/red-team consult completed under FIX_PROMPT.
Status: implemented; independent QA/red-team and root full-suite gate PASS.
Consult 010 is authoritative.

## Problem (verified)
- `corroborate(by="human")` on a self-minted `Source(kind="human", integrity="trusted")` flips a
  poisoned memory from tainted to preserved and downgrades gate block→reverify (audit report).
- MCP + REST share one token with revoke/reinstate/corroborate power, so a prompt-injected agent
  has operator powers. `KNOWN_ISSUES.md #11` "accepted" must flip to addressed-or-disclaimed.

## Fix direction
- Two roles per tenant: `agent` (ingest events/sources/memories/actions, read/impact/gate) and
  `operator` (revoke/reinstate/corroborate by=human|scanner, mint integrity=trusted sources).
- Prefix token: `ped_a_…` vs `ped_o_…`, both stored hashed. `TenantRegistry` mints both at create.
- Existing tokens (prefix-neutral `ped_…`) → map to `agent` role (least privilege migration).
- `Authorization: Bearer` middleware actually consumes the operator token (closing red-team F-2).

## Test/acceptance (FIX_PROMPT)
- laundering repro → 403 with agent token; agent token cannot invoke revoke/reinstate or corroborate
  by=human via REST or MCP; operator can; existing tests migrated; docs/qa/redteam-P-015.md has
  before/after attacks.
- P-016 interim header-not-consumed note in README resolves to "consumed".
- Public demo operator-secret handling remains a deployment gate (D1); no public deploy claimed.

## Implemented contract and evidence pending review

New creation delivers named agent/operator bearers once; `token` remains the agent
alias. Only SHA256 digests persist, and credential repr hides both values. Stored
matching digest plus prefix consistency resolves an immutable principal; legacy
token_sha256 remains agent authority. Cache hits recheck active status and stored
digest, so rotation by another process invalidates prior authority on the next call.
Lookup misses still scan tenants until P-020; no constant-time lookup claim here.

Explicit `pedigree admin issue-operator --id <tenant> [--rotate]` recovers operator
access; issuance refuses existing operator state without explicit rotation. Registry
Tenant(id) index/unique constraint plus CREATE prevents concurrent create overwrite.
A write-first credential_epoch update serializes conditional issuance on the registry
row. Actual independent-client builder probes admitted one valid result per race.
Existing duplicate registry IDs cause schema initialization to fail; no automatic
destructive deduplication or credential recovery is attempted.

Global admin headers remain deployment administration only and do not elevate an
agent bearer. Ordinary file/rules captures are untrusted agent evidence; explicit
human/scanner/trusted assertions reject with forbidden. Entire event batches check
these assertions before admission/writes. Operator-positive fixtures use operator
credentials; agent-denial tests remain separate. E3 authored replay uses operator
authority for its explicit trusted fixtures, not a model/runtime integration.

MCP uses installed SDK per-message request headers and a reset ContextVar. HTTP
header/tool conflicts reject without fallback; configured stdio defaults must resolve
agent. Explicit operator MCP invocation is permitted per consult decision/dissent.
Claude/OpenCode adapters reject configured ped_o_ bearers locally before networking;
legacy credentials stay agent on the server. Existing hook outage fail-open behavior
remains documented; local operator rejection is not an installed-runtime claim.

Seeder saves both roles for new tenants and preserves existing credential files.
UI requests operator credentials, held in page memory only. Lost legacy operator
access requires explicit admin issuance; startup does not silently rotate anything.
The secret scanner recognizes role-prefixed bearer shapes outside assignments.
