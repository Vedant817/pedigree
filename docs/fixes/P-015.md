# P-015 — Role separation: agent vs operator (FIX_PROMPT C1)

Owner: Phase C. **Consult mandatory with P-013 red-team + eval-statistician before implementation.**
Status: spec drafted; do NOT implement until clarifying consult done (C1 touches auth core).

## Problem (verified)
- `corroborate(by="human")` on a self-minted `Source(kind="human", integrity="trusted")` flips a
  poisoned memory from tainted to preserved and downgrades gate block→reverify (audit report).
- MCP + REST share one token with revoke/reinstate/corroborate power, so a prompt-injected agent
  has operator powers. `KNOWN_ISSUES.md #11` "accepted" must flip to addressed-or-disclaimed.

## Fix direction
- Two roles per tenant: `agent` (ingest events/sources/memories/actions, read/impact/gate) and
  `operator` (revoke/reinstate/corroborate by=human|scanner, mint integrity=trusted sources).
- Prefix token: `ped_a_…` vs `ped_o_…`, both stored hashed. `TenantRegistry` mints both at create.
- Existing tokens (prefix-neutral `ped_…`) → map to `agent` role (least privilege migration).
- `Authorization: Bearer` middleware actually consumes the operator token (closing red-team F-2).

## Test/acceptance (FIX_PROMPT)
- laundering repro → 403 with agent token; agent token cannot invoke revoke/reinstate or corroborate
  by=human via REST or MCP; operator can; existing tests migrated; docs/qa/redteam-P-015.md has
  before/after attacks.
- P-016 interim header-not-consumed note in README resolves to "consumed".
- Docker public demo disables admin/operator secret (D1 path).
