# P-013 — Admin auth fail-closed (FIX_PROMPT A3)

## Problem (verified in-tree)

- `src/pedigree/api/routes/admin.py:10,20`: `if registry.has_tenants():` — with an EMPTY
  registry, `POST /admin/tenants` and `GET /admin/tenants` skip the admin check entirely;
  a fresh deploy is owned by the first caller. (Live probe: with tenants present,
  no-token/wrong-token already return 401 — only the bootstrap path is exposed.)
- Token compared with `header != expected` (not constant-time).
- `.env.example` ships `PEDIGREE_ADMIN_TOKEN=change-me-admin`.
- No first-run CLI path (`pedigree admin create-tenant` absent).

## Fix plan

1. `api/routes/admin.py`: delete the `has_tenants` branch; both routes always require
   `X-Admin-Token`; compare with `hmac.compare_digest` on encoded bytes; fail-closed
   when the expected token is empty.
2. `config.py`: add `pedigree_env: str = "dev"`; add
   `DEV_ENVS = {"dev","test","local"}`, `KNOWN_DEFAULT_ADMIN_TOKENS = {"change-me-admin",
   "change-me","changeme"}` and `admin_token_problem(settings) -> str | None` (shared guard).
3. `api/app.py` (`create_app`): if `admin_token_problem(settings)` is not None ->
   raise `RuntimeError` (refuse to start in non-dev with empty/default token).
4. `cli.py`: new `pedigree admin create-tenant --id <tenant> [--cap N]` — uses the same
   guard; reads `PEDIGREE_ADMIN_TOKEN` from the environment; creates via `TenantRegistry`
   directly against FalkorDB (first-run path without HTTP bootstrap); prints tenant id +
   one-time token; exit code 2 with a clear stderr message on refusal.
5. `.env.example`: note that non-dev startup refuses empty/known-default tokens.

## Tests (land right after the P-016 QA freeze)

`tests/security/test_admin_auth.py` (TestClient; cleanup every tenant created):

- fresh-registry simulation: `monkeypatch.setattr(TenantRegistry, "has_tenants", lambda self: False)`
  -> `POST /admin/tenants` no header = 401 and `GET` no header = 401. **RED today** (≥1 of these
  returns 200/2xx); GREEN after the fix (routes never consult the flag anymore).
- wrong token -> 401; correct token -> 200; `GET` same matrix.
- guard matrix via `create_app(db=db, settings=Settings(...))`:
  - prod + default token -> RuntimeError; prod + empty -> RuntimeError;
  - prod + strong token -> app builds; dev + default -> app builds.
- CLI: subprocess `python -m pedigree.cli admin create-tenant --id <t>`:
  env strong token -> exit 0, stdout has tenant id + `ped_` token (cleanup after);
  prod + default token -> exit 2 + refusal message; missing token (prod) -> exit 2.

Compatibility check (grep-verified): every existing test call to `/admin/tenants` already
sends `X-Admin-Token`; nothing relies on the bootstrap bypass.
