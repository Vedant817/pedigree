## Problem (verified in-tree 2026-10-16)

1. `src/pedigree/cli.py:180-184` calls `build_mcp(settings, default_tenant_id=..., default_tenant_token=...)`
   positionally; `src/pedigree/mcp_server.py:240` signature is
   `build_mcp(db=None, settings=None, default_tenant_id=None, default_tenant_token=None)`, so `settings`
   lands in `db` -> first tool call raises `AttributeError` ('Settings' object has no attribute used by Db).
2. `opencode.json:6` and README claim `http://127.0.0.1:8000/mcp`; `docs/02-ARCHITECTURE.md:15` shows
   "MCP Streamable HTTP /mcp", but `src/pedigree/api/app.py` mounts only StaticFiles at `/` -> `GET /mcp` 404.

## Decision (consult skipped — answer already in project docs, cited)

- `docs/02-ARCHITECTURE.md:50`: "**Mounting MCP in the same ASGI app** | one port/one deploy ...
  **[V]** `MCPServer.streamable_http_app()` mounts in FastAPI (needs `lifespan` running
  `mcp.session_manager.run()`; mount at `/` LAST) — working spike `tech/examples/mcp/mount_in_fastapi.py`
  incl. bearer middleware, mcp 2.3.0. Fallback if it breaks: second process on another port."
- 30-second experiment (2026-10-16, venv): installed `mcp==2.3.0`;
  `MCPServer.streamable_http_app()` returns `Starlette` with exactly one route `'/mcp'` (`Route` wrapping
  `StreamableHTTPASGIApp`); `MCPServer.session_manager` exists.
- Mechanism: single port. In `create_app`, build the MCP server from the app's own `db`/`settings`; add a
  FastAPI lifespan that runs `session_manager.run()`; mount ONE root ASGI dispatcher at `/` — paths under
  `/mcp` go to the MCP ASGI app (path unchanged, so its `/mcp` route matches), everything else goes to the
  existing StaticFiles UI. No second port, no route renames, UI unchanged.

## Scope notes

- Auth on `/mcp`: tool calls authenticate by the `token` **argument** (existing tool contract). The HTTP
  `Authorization` header is NOT consumed by the mount yet; transport-level auth and the agent/operator
  role split are explicitly P-015 scope (FIX_PROMPT C1: "MCP and the hook use the `agent` token only").
  Red-team to review the interim surface; caveat documented in FEATURES/README touch-ups.
- Import hygiene: `build_mcp` is imported function-locally in `app.py` so `import pedigree.api.app` does
  not import `mcp_server` (rest of P-025 not in this item).
- Test hygiene (P010-QA-2): every new test deletes the graphs/tenants it creates; retrofit the same
  teardown into `tests/integration/test_mcp.py` so it stops leaking `ped:mcp*` graphs.
