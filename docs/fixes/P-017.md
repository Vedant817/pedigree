# P-017 — Capture web and shell reads

Status: implemented 2026-10-17. Source: `FIX_PROMPT.md` PHASE F item F1.
Real Claude Code session recording stays human-only (`FIX_PROMPT.md` §13).

## Acceptance

1. `WebFetch` → `Source(kind=web, integrity=untrusted)` plus a session READ.
   URLs with userinfo are not stored. `WebSearch` stores
   `websearch:sha256:<digest>` and does not send the query text.
2. `Bash` `cat` / `head` / `curl` / `wget` on a path or http(s) URL records a
   READ. The action's `relied_on` is those nodes only. A write-shaped curl or
   wget does not record a READ.
3. `ssh`, `scp`, and `sudo` match command tokens. `git push`, `rm -rf`, and
   `curl -X POST` match the command, not a mention inside `echo`.
   `cat ~/.ssh/config` and `head ~/.ssh/authorized_keys` stay reversible/low.
   `ssh host` stays irreversible/high.
4. The pre-tool gate still submits the session id with no explicit
   `relied_on`. ADR-007's read-window floor is unchanged: empty dependencies
   plus a session that has read a now-revoked node still returns `reverify`.
5. Fixtures in `tests/fixtures/claude/` are synthetic. The adapter README says
   so. No installed-runtime capture is claimed.

## Tests

- `tests/unit/test_gate.py` — `.ssh` false positive and real `ssh`/`scp`/`sudo`.
- `tests/unit/test_claude_hook.py` — web, curl, bash read linkage, fixture replay.
- `tests/integration/test_p017_capture.py` — revoking an earlier unrelated
  source does not taint the bash read; revoking the file it read does.

## Follow-up, same day

QA on `d9fed01` found capture holes the first tests did not cover. The hook now
keeps `cat -n` / `head -n` / `sudo -u user cat` on the named file, treats
`--json`, `--data-ascii`, `--request POST`, `-T`, and wget `--body-data` as
writes, and redacts URL userinfo plus Authorization, Cookie, X-Api-Key, `-u`,
`--user`, and `--password` values before `/v1/gate` and `/v1/events`. The
classifier unwraps `env`, `command`, `exec`, `eval`, and `bash -c`, recognises
`ssh.exe` and `$'ssh'`, and runs the unparsed-command fallback only on the
segment shlex could not tokenise. The empty-`relied_on` read-window floor is
unchanged.
