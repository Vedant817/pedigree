# P-021 — Strict input validation, no exception leaks (FIX_PROMPT C3)

Owner: Phase C. Status: implemented; independent QA/red-team and full gate PASS.
Authoritative contract: [consult 011 decision](../consults/011-p021-validation/decision.md), ADR-012.

## Problem (verified)
- `/v1/events` with `"conf":5`/`"artifacts":5` → 500 with `{"message":"'int' object is not iterable"}`;
- `derived_from:"abc"` iterated per character → fuzzy graph.
- NUL in URI/text causes internal DB errors; the live consult observed newline/tab/DEL
  persisting. Identity strings must reject these controls without rewriting them.
  Generic handlers returned `str(exc)`.
- Oversize body via `Transfer-Encoding: chunked` bypasses `BodySizeMiddleware` (red-team **F-4**).

## Fix plan
1. Pydantic models `extra="forbid"`, item-level `list[str]` with item length 1-128 and regex
   `[A-Za-z0-9._:/@#_-]` patterns where appropriate, bounded lengths, NUL rejected in uri/text.
2. `BodySizeMiddleware` counts actual bytes (pure ASGI wrapper), so chunked bodies are capped at
   256 KiB too (passes `max_request_body_size=256*1024` to `streamable_http_app` for /mcp parity).
3. Unexpected errors return only `{"code":"internal","correlation_id":...}`.
   Diagnostics log class, generated ID and bounded stack-frame metadata, never raw
   exception messages, causes, locals or exc_info. Raw traceback logging is superseded
   by ADR-012 because exception values can contain credentials.
4. Shared strict tool validation runs before SDK parsing can discard extras or echo
   rejected inputs. The full call includes authentication/schema resolution. HTTP and
   stdio JSON-RPC parser errors are sanitized before SDK rendering or logging.

## Tests first
- table-driven malformed-event shapes (`conf:5`, `artifacts:5`, `derived_from:"abc"`, NUL/newline uri,
  oversized scalar, extra keys) → 422 `invalid_argument` for REST, never 500.
- chunked 300 KB → 413 too_large for `/v1/events` and `/mcp`.
- log capture test: forced engine/auth/schema faults return safe correlation IDs;
  response and actual server logs contain no injected secret or exception string.

## Acceptance
- every malformed shape 422; no response body has a Python exception string; red-team transcripts null.
- `tests/security/test_security_F06`-facing smoke; dogfood S08 + S09 flip to PASS.

## Compatibility and measured limits

Known aliases, optional null producer lists, session inheritance and generic fallback
for unknown runtimes remain supported. Unknown operations, extras, conflicting aliases,
scalar list substitutions and malformed items now reject before batch writes. The old
ignored `mkind` field in a dogfood event was removed; direct memory creation still supports it.
LF/tab remain valid prose; identity strings reject C0/DEL without trimming. Validation
errors use a fixed typed envelope, without input/ctx or arbitrary field names. Typed
engine errors retain fixed messages and reviewed numeric details only.

Pure ASGI admission counts actual bytes before downstream parsing, including chunked
requests. Correlation middleware contains failures before Starlette can rethrow them
to server logging; a response already started cannot be replaced with another status.
MCP stdio containment uses isolated, shape-checked SDK 2.3 runner plumbing. The HTTP
body cap does not bound the SDK's stdin line allocation. No site-packages edits.

Independent QA: [report](../qa/P-021.md), 71 distinct cases including 50 independent probes.
Real HTTP fault logs and chunked bodies, genuine SDK HTTP and CLI stdio are distinguished
from synthetic ASGI framing. Root dogfood now 22 PASS / 1 known expected failure
(application metrics), with zero run-owned leftovers. Independent red-team: 29 passed
in 17.48s. Root `make check`: 698 passed, 2 skipped, 3 deselected, 1 xfailed in
277.62s; Ruff, tracked secrets and numbers PASS. The red-team file was added after
that suite collected; its 29 cases separately passed against the same source. Final
collection accounts for every case: 730 selected, with 3 perf cases deselected.
