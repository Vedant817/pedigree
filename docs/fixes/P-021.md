# P-021 — Strict input validation, no exception leaks (FIX_PROMPT C3)

Owner: Phase C. Status: spec.

## Problem (verified)
- `/v1/events` with `"conf":5`/`"artifacts":5` → 500 with `{"message":"'int' object is not iterable"}`;
- `derived_from:"abc"` iterated per character → fuzzy graph.
- NUL/newline in `uri` → database error; generic handler returns `str(exc)` (app.py:33, mcp_server.py:28).
- Oversize body via `Transfer-Encoding: chunked` bypasses `BodySizeMiddleware` (red-team **F-4**).

## Fix plan
1. Pydantic models `extra="forbid"`, item-level `list[str]` with item length 1-128 and regex
   `[A-Za-z0-9._:/@#_-]` patterns where appropriate, bounded lengths, NUL rejected in uri/text.
2. `BodySizeMiddleware` counts actual bytes (pure ASGI wrapper), so chunked bodies are capped at
   256 KiB too (passes `max_request_body_size=256*1024` to `streamable_http_app` for /mcp parity).
3. Generic 500 handler returns only `{"code":"internal","correlation_id":...}`; full detail
   logged server-side at ERROR with exc_info=True. Same in MCP `_call` path.

## Tests first
- table-driven malformed-event shapes (`conf:5`, `artifacts:5`, `derived_from:"abc"`, NUL/newline uri,
  oversized scalar, extra keys) → 422 `invalid_argument` for REST, never 500.
- chunked 300 KB → 413 too_large for `/v1/events` and `/mcp`.
- log capture test: 500 from a forced fault → body has no `ped_` token nor Python exception string;
  server log contains `exc_info`.

## Acceptance
- every malformed shape 422; no response body has a Python exception string; red-team transcripts null.
- `tests/security/test_security_F06`-facing smoke; dogfood S08 + S09 flip to PASS.
