# P-014 — Enforce quotas on every write path (FIX_PROMPT C2)

Owner: Phase C. Status: spec.

## Problem (verified)
- `/v1/events` bypasses `node_cap`: with cap=5, one request created 55 nodes (dogfood S07).
- Sessions/corroborations/null paths unchecked; only ingest `remember`/`record_source`/`record_action`
  check `node_count >= cap` (or instantiate quota partially).

## Fix plan
1. One `enforce_quota(tenant, add=n)` in the ingest engine (engine/ingest.py), used by all write
   paths (events, remember, record_source, record_action, corroborate, sessions), atomic per request
   via tenant lock: after deciding, increment "tentative" count or better count `node_count` vs cap
   under lock + reserve.
2. `/v1/events` maps `QuotaExceeded` → 429/quota_exceeded; no partial write when exceeded (events
   transactional already; ensure append-then-check happens before it starts).

## Tests first
- dogfood S07: a cap-5 tenant `/v1/events` creating 55 → 429 `quota_exceeded`, node_count stays 5.
- evidence: cap=5, create 5 individually then one of 1 → 429 quota_exceeded.
- concurrent: two simultaneous batches totalling cap+1 → one 429 (timing race documented).

## Acceptance
- no path creates >cap nodes; unit test asserts exact rejection. S07 flips to PASS.
