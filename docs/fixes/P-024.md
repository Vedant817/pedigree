# P-024 — Reconcile children born during/after a revoke (FIX_PROMPT B3)

Status: spec (2026-10-16). Loop: SPEC -> red test (threaded writers) -> implement -> `make check`
-> dogfood -> QA (`docs/qa/P-024.md`) -> docs -> commits.

## Problem (audit-verified)

Under concurrent writes, nodes created during a revoke end up born-quarantined and stay
`quarantined` forever: the revoke finishes, no `running` Revocation remains, and nothing ever
re-derives them. Threaded probe: 54/358 nodes stuck in one run (0 leaks of `ok`/`preserved`, so
it is safe but wrong). Root cause: `resolve()` quarantines `ok`/`preserved` nodes and writes
final statuses only for nodes discovered via the revoked roots; late arrivals (or arrivals the
barrier missed) are never revisited after `_finish`.

## Fix plan

1. Shared helper `reconcile(db, gname, *, trace)` (engine/revoke.py or engine/compute side):
   when no `running` Revocation exists for the tenant (`Q_RUNNING_REVOCATIONS` empty),
   select `quarantined` nodes, run `compute_final` on them **using all remaining revoked roots**
   as the root set, write final statuses, verify once (same loop shape as `resolve`).
   Deterministic, idempotent, tenant-locked, bounded.
2. Call it: (a) at the end of `resolve()` after the verify step (so a normal revoke cleans up
   its own stragglers), (b) inside P-011's resume path when no running row remains, and
   (c) expose `pedigree reconcile [--tenant ID]` CLI (all active tenants when omitted).
3. Extend `check_invariants` with: **"no `quarantined` node while no Revocation is `running`"**
   (per tenant). This is the detection rule the oracle test uses.
4. Interaction with P-012: reconcile and reinstate must share the same "remaining roots"
   definition (all active revocations + individually-revoked nodes) once B2 lands; keep the
   helper single-sourced.

## Tests first

1. Threaded probe: N writer threads ingesting chains (respecting `tenant_lock` semantics) while
   a revoke runs; 12 runs; after the revoke + reconcile -> **zero `quarantined`**;
   statuses equal the oracle (P-012's `tests/oracle.py`, or hand-computed for small shapes
   until it exists); `check_invariants == []`.
2. Invariant coverage: fabricate a quarantined node with no running Revocation ->
   `check_invariants` reports the new rule (and reverting the reconcile call makes the probe
   fail it).
3. CLI reconcile on a crafted straggler state.

## Acceptance (FIX_PROMPT B3)

- 12 threaded runs: zero `quarantined`, oracle-equal statuses; new invariant present;
  `make check` green; dogfood heavy scenario (revoke under load) reports zero stuck nodes.
