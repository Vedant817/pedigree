# P-023 — Isolation and concurrency suite (F-15 subset)

Status: in progress (Phase E, Sat 2026-10-17). Source: `FIX_PROMPT.md` PHASE E item E3.
Owner: feature session; closures decided by an independent QA pass.

`tests/isolation/` treats the tenant boundary as the product's trust boundary and
tries to break it with concurrent interleavings.

## Acceptance

1. **Per-route cross-tenant 404.** For every surface that takes an id — REST
   `GET /v1/blame/{id}`, `GET /v1/impact/{id}`, `POST /v1/revoke` (`root_id`),
   `POST /v1/gate` (`relied_on`), and the MCP tools `pedigree_blame`,
   `pedigree_impact`, `pedigree_revoke`, `pedigree_check_action` — tenant B's valid
   credential used against tenant A's ids answers *not in the graph* (REST 404 with
   code `not_in_graph`; MCP `ok: false` with the same code). Never 200 with A's data,
   never another status, never a 500.
2. **Concurrent interleavings across two tenants.** Two threads (one per tenant)
   driving revoke/ingest simultaneously against the real FalkorDB produce exactly the
   single-tenant results: statuses, revocation rows and the node/edge set of each
   tenant graph equal the same operations run alone; a hypothesis strategy generates
   the small lineage DAGs (expected statuses may be computed with the independent
   `tests/oracle.py` global fixpoint).
3. **Transport independence.** The same cross-tenant assertions hold through REST
   (`TestClient`) and MCP (`build_mcp`), including a hook-style `check_action`
   payload from tenant B that lists tenant A's ids: the decision is computed from
   B's graph only.
4. **No leak in error surfaces.** A cross-tenant attempt must not echo the other
   tenant's id (beyond the requested id), node properties, or tenant id in response
   bodies, error payloads or `pedigree.access` lines.
5. **Hygiene.** No new dependencies; every graph and registry row the suite creates
   is removed even on failure (the `fresh_graph` / registry-delete pattern); anything
   that needs more than a few seconds is marked `@pytest.mark.slow` so `make
   test-quick` stays fast, while `make check` still runs it.

Out of scope: per-tenant FalkorDB ACL users (FIX_PROMPT: only if time remains,
after a consult; the shared dev FalkorDB has no ACL configured).
