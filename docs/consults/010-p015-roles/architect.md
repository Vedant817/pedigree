# Architect recommendation

**Decision: A, with an explicit distinction between agent configuration and operator invocation.** FIX_PROMPT C1 says both “MCP and the hook use the agent token only” and “operator token can” after the REST/MCP denial requirement (`FIX_PROMPT.md:90-91`). Configure shipped MCP/hook examples and defaults exclusively with agent credentials; permit an explicitly supplied operator bearer on MCP tools. Never fall back from a supplied invalid/agent token to an operator default. This supersedes consult 007's blanket MCP prohibition (`decision.md:28`); document that change. If “agent-only” means protocol prohibition, the two acceptance clauses conflict; my recommendation favors the explicit operator-can test.

**Principal:** resolve to an immutable `{tenant_id, role, status, node_cap, created_at}` principal. Determine role from the stored matching digest slot, then verify prefix consistency; a caller-controlled prefix is never authority. Keep tenant administration data separate where practical. Middleware stores the principal, tenant and graph; MCP resolves the same principal and checks requested tenant equality. Current REST stores only tenant (`auth.py:65-66`), MCP returns only tenant/graph (`mcp_server.py:45-74`). Add one shared `require_operator` policy used by both interfaces, before mutations and quota admission.

Agent is the baseline capability set; operator adds revoke/reinstate, trusted source claims/kinds and human/scanner corroboration. Explicit prohibited assertions return forbidden, including event batches, rather than silently lowering integrity. Global X-Admin-Token must never upgrade an agent bearer. Keep deployment-wide create/list/resume controls deployment-admin-only; tenant operator administration must be explicitly tenant-scoped (`routes/admin.py:21-43`).

**Issuance/migration:** generate independent random `ped_a_...` and `ped_o_...` credentials; store only their SHA256 digests in additive fields. Preserve existing `token_sha256` exclusively as legacy agent authority (`registry.py:59-78,97-122`; `queries.py:338-339`). Return `token` as the agent compatibility alias plus `agent_token` and `operator_token`, once. Existing rows get no automatic operator privilege. Supply a local administrative issuance command for existing tenants, invalidating caches; never regenerate silently on startup. Defer indexed resolution to P-020.

**Verification:** migrate operator-positive tests, UI and demo seeding to operator credentials; keep normal ingest/hook/MCP fixtures agent. Test both interfaces, default/explicit precedence, prefix forgery, legacy downgrade, revoked tenant, cross-tenant operator, valid admin header plus agent denial, and laundering snapshots showing no mutations. Current trusted tests depend on a global header (`test_capture_trust.py:49-53`), so preserving their assertions unchanged would preserve the vulnerability.

Confidence: high on architecture; no runtime implementation verified by this consult. Risks: accidental operator provisioning to agent environments and undocumented legacy operator recovery.
