# Domain recommendation

**Observed on actual module 42201:** eight independent connections against an initialized, owned graph ran `MATCH(n:Node) WITH count(n) AS used WHERE used+$add<=$cap UNWIND $ids AS id CREATE(n:Node {id:id}) RETURN n.id` with cap=1/add=1: **4 admitted; count=4**. A single Cypher statement alone is insufficient. Prepending `MATCH(q:Quota {id:$quota}) SET q.seq=coalesce(q.seq,0)+1 WITH q` produced **1 admitted; count=1; seq=8**. Both temporary graphs were deleted and absence verified. These are small connection-level experiments, not cross-process acceptance tests.

Use an existing, unique graph-local metadata anchor and an explicit write **before** reading admission state. Pin the execution plan and independently prove contention; do not assume a conditional counter read before SET is atomic. Never use the process-local revoke lock as the cross-worker guarantee. Initialize metadata before serving writes, outside concurrent admission.

For strict request admission, resolve canonical source identities, existing sessions and repeated in-batch identities after acquiring this write barrier. Compute distinct **new nodes**, then guard the complete normalized batch and apply its creates/edges in that same static parameterized query. Separate Python preflight plus sequential engine calls still races and can partially ingest. Existing `events.py` is sequential; its transactional claim is false. Reservation counters across multiple queries add crash recovery, orphaned capacity and duplicate-race problems; avoid claiming those are the smallest equivalent transaction.

Keep quota policy independent of `api.registry`: bootstrap a registered tenant’s graph metadata from its existing `TenantRecord.node_cap`; ingest consults graph policy. No metadata means standalone engine mode, preserving unregistered `fresh_graph`; public transports must require registered authentication/policy bootstrap. Missing metadata on a registered graph must fail closed, not silently disable quota.

Accounting decision required: existing `node_count` counts every physical node, including Revocations. Metadata must be excluded explicitly and schema/invariant checks adapted. Preserve each tenant’s configured cap; do not replace it with settings defaults. Recommended operational exception: revoke/reinstate journals may grow above cap so safety actions remain available; they still consume subsequent ingest headroom. State this exception instead of claiming all physical writes remain under cap. Corroboration/READ only add edges: delta=0 and must work at cap.

Acceptance: cap-boundary session creation/reuse; identical source retry at cap; duplicate identities within batch; mixed REST/MCP/events competing from separate processes; rejected batch leaves nodes **and edges** unchanged; metadata bootstrap and custom cap; existing Revocations; unregistered engine regressions. Full retry-idempotency for memory/action requires an explicit stable operation identity; generated IDs cannot provide it.
