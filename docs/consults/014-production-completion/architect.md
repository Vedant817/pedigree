# Architect response

**Recommendation.** Keep the existing token-derived graph contract and add one explicit tenant-scoped `Db` factory. Retain a separate administrator `Db` for registry/provisioning/health. Resolve bearer before selecting a tenant connection; require REST, events, MCP, and startup recovery to obtain the same scoped connection. Provision deterministic tenant ACL identities with deployment-secret-derived passwords; do not reuse bearer tokens as DB passwords. ACL failures must fail requests, never fall back to admin. Keep `pedigree_db_acl=false` an explicitly documented reduced-isolation mode.

**Evidence.** `src/pedigree/db/client.py:142-151` presently selects only deployment credentials; `api/auth.py:55` initializes tenant schema through the shared DB; `mcp_server.py:286-429` passes `self.db` to tenant operations. Existing ACL proof permits exact main graph and what-if descendants but excludes checkpoint descendants (`tests/security/test_acl_mechanism.py:25-28,53`). Extend only to `~ped:<tenant>:ck:*`; deny registry, other tenants, `GRAPH.LIST`, ACL administration, arbitrary Redis commands. `whatif.py:114,215` currently enumerates graphs: replace tenant execution with scoped known-copy metadata or a narrowly privileged cleanup coordinator. DDL may need privileged provisioning; verify its real command permissions independently.

**Checkpoint/restore.** Use immutable bounded checkpoints, operator authorization, validated names (`config.py:166-170`), no silent overwrite, and shared tenant maintenance admission covering every read/write transport. Restore must not expose a deleted/partially copied graph. Verify atomic graph replacement support experimentally on the isolated DB before choosing an implementation; `GRAPH.COPY` alone plus delete/copy is insufficient. If unavailable, implement a durable restore journal and fail-closed maintenance state across process restarts, retain rollback graph, and reopen only after schema/invariant checks. Update ADR/public contracts. Do not claim crash safety from process-local locks.

**Spool/startup.** Hook requests currently have only direct HTTP delivery (`adapters/claude/pedigree_hook.py:36-51`). Persist events atomically before delivery; namespace by endpoint and credential fingerprint, bound disk usage, replay oldest first, use stable idempotency keys, and never replay gate approvals. Production defaults already disable seeding/login (`config.py:85-86`; `scripts/entrypoint.sh:6-8`); production should reject either enabled setting and require durable DB storage.

**Acceptance/release blockers.** On fresh port 6381: two real tenant credentials through REST/MCP; raw tenant DB cross-read/write/copy denial; provisioning failure without admin fallback; restart persistence; checkpoint equality and operator-only restore; concurrent mutation exclusion; kill/restart during restore; spool offline/restart/replay exactly once with token rotation isolation; empty production first boot. These are proposed checks, not executed proof. Atomic replacement support remains unverified.
