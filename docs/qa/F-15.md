# QA report - F-15 isolation and concurrency (E5)

Verdict: **PASS** for the tested surface; ACL *wiring* is an open item (KNOWN_ISSUES 18) and is
not claimed here.

- `.venv\Scripts\python.exe -m pytest -q tests/evals/test_oracle_agreement.py` -> `11 passed`
  (1000 random DAGs, engine vs independent oracle; real-FalkorDB revoke cross-check).

## Adversarial / verification matrix

1. **API isolation matrix.** Tenant B's token: `blame`/`impact`/`revoke`/`corroborate` on A's ids
   -> 404 (`not_in_graph`), never an empty success; the gate for A's ids with B's token ->
   `reverify` (unknown lineage is never "safe"); A's afterwards graph unchanged and invariants
   clean. PASS.
2. **Threaded stress (docs/05 AT2.3 shape).** 20 tenants x 8 writer threads, 6 nodes each:
   after the join every graph passes `check_invariants(expected_tenant=...)`, holds exactly the
   nodes its own writers produced (6 Sources - the 8 identical writers converge on one node per
   uri - plus 48 memories and 48 actions), and contains zero foreign-tenant nodes. PASS.
3. **Revoke racing ingest.** Two writers deriving from the root while a revoke runs: either the
   writes succeed or they fail with a typed `Conflict` ("parent disappeared" is refused by
   design); no crash, invariants clean, the root ends `revoked`. PASS.
4. **ACL mechanism.** Real ACL users scoped to `~ped:<tenant>` and `~ped:<tenant>:wi:*`:
   own-namespace read/write OK; reads of another tenant's graph, of `ped:zzz` and of
   `pedigree:registry` denied; `GRAPH.COPY` inside the namespace OK, into a foreign namespace
   denied. PASS (verified on v4.22.1).

## Findings and fixes during the round

- **Fixed (HIGH):** shared single connection -> per-thread connections (measured before/after).
- **Fixed (HIGH):** the hash-less identity race (see `docs/qa/F-13.md`) surfaced *only* under
  this stress test - it is now covered by an identity test.
- Test-hygiene finding (not a product defect): writing to a tenant graph that has not had
  `ensure_schema` run lets concurrent writers create duplicate identities, because the
  constraints do not exist yet. The API always runs `ensure_schema`; direct engine callers must
  too (recorded as KNOWN_ISSUES 20).

## Residual, stated not softened

- ACL users are verified but not wired: the shipped service isolates at the API level
  (bearer token -> one graph per tenant), which is what tests 1-3 cover.

**Verdict: PASS.**
