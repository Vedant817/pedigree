Verdict: PASS for the observed strict-validation, batch prevalidation and error
containment boundaries below. This is local repository/real FalkorDB/loopback TCP

safe exception class/frame diagnostics supersede the old fix spec's raw `exc_info`

## Adversarial cases and evidence

1. Twenty-six malformed bad-tail event cases put a valid Source creation first,
   then wrong scalar/container/item types, booleans, nulls, unknown operations,
   extras, malformed hashes, overlong URI, missing session/read IDs, control
   characters or conflicting aliases. Every request returned 422
   `invalid_argument`; exact sorted nodes/properties and edges/properties remained
   unchanged. Unknown field names and values were not reflected.
2. Strict ordinary REST Source/Memory/Action/revoke/gate bodies rejected string
   lists, boolean text/depth and string booleans. Exact graph snapshots were
   unchanged. This reaches the public endpoints, not only Pydantic constructors.
3. A valid batch using unknown-runtime generic fallback and legacy operation,
   Source-kind, tool-name, summary/title and dependency aliases succeeded. LF/tab
   prose reached the Memory content hash unchanged, and the derived edge resolved
   to the canonical Source identity. Default text privacy intentionally stores
   an empty text property; the check uses the expected SHA-256 instead of claiming
   plaintext storage.
4. Eight direct installed-SDK tool cases rejected malformed lists/items,
   controls, coercible booleans and extras with safe `invalid_argument`. The
   temporary credential and caller canaries were absent from returned SDK results;
   exact graph snapshots were unchanged.
5. Actual loopback TCP, HTTP/1.1 chunked requests in multiple 17,000-byte chunks
   exercised the shared ASGI byte guard at `/v1/events` and `/mcp`: exactly 262144
   bytes reached the downstream endpoint once; 262145 bytes returned 413 before
   downstream dispatch. These wire probes exercise the actual middleware with a
   minimal endpoint, not the application parsers. The combined root boundary
   tests separately cover no-length and understated Content-Length synthetic ASGI
   framing. An independent disconnect mid-body produced no dispatch or response.
   False framing/disconnect are synthetic evidence, not claims about legal wire
   Content-Length behavior.
6. Actual uvicorn TCP requests to the full application's stats route forced
   engine and authentication RuntimeErrors containing private canaries while
   sending a hostile correlation header. Both returned 500 `internal` with a
   generated UUID matching the response header. The canary was absent from
   responses and captured application/uvicorn logs; diagnostics retained class
   and frame metadata without raw `exc_info`. This checks server logging after
   application exception handling, not just TestClient output.
7. A real CLI stdio subprocess processed initialize, initialized notification and
   a malformed health-tool call. It exited zero, returned typed
   `invalid_argument`, and disclosed neither canary nor unknown argument name in
   stdout; stderr also had no canary. A real TCP standalone SDK streamable-HTTP
   client got the same safe tool result. A malformed JSON-RPC envelope carrying a
   secret request ID got a fixed 400 protocol error without request-ID reflection
   or log canary. These preserve protocol errors as protocol errors.
8. A forced secret-bearing MCP schema-resolution RuntimeError before the tool
   body returned safe `internal` plus UUID, no response/log canary, and an exact
   unchanged graph. The installed SDK wraps this fault as `UnexpectedToolError`;
   that wrapper class appears in sanitized diagnostics. This probe does not claim
   the nested RuntimeError class or message is retained for operators.

## Findings and corrections during review

No unresolved product defect was found in these independent probes. The initial
review run was 43 passed/2 failed because the reviewer initially used the obsolete
`/v1/gate/check` path and expected plaintext Memory storage despite the existing
privacy default. Both test assumptions were corrected to the actual public route
and content hash; the final combined run passed. Initial UUID-format and SDK
wrapper-class assumptions were similarly corrected to accept valid UUID hex and
the observed installed wrapper. These were test-author errors, not claimed
product RED-to-GREEN reproductions.

The root's stronger ASGI correlation/error boundary was already present before
the independent real uvicorn log probes. Those probes verify the corrected
boundary; they do not independently establish its earlier failure.

## Ownership and limits

Every graph and registry row created here has a unique `vreview...` tenant ID and
is removed by exact identity in `finally`. Wire tests own bound sockets and join
their own server threads; stdio owns and waits for its subprocess. Session
ownership sentinels verified an unrelated graph and registry row were unchanged.
No broad registry cleanup, external providers, deployment or real credential
printing was used. Earlier historical data is outside this review's cleanup scope.

Batch snapshots prove validation rejection before mutations, not general database
transactionality for later engine/DB failures. Byte-limit acceptance does not
prove every HTTP server/proxy's framing semantics. The SDK probes target the
installed local version; future SDK contract changes require renewed evidence.
