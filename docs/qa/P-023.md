## What was verified

Command: `.venv\Scripts\python.exe -m pytest tests/isolation -q`
Result: `6 passed in 2.24s`, `EXIT=0`.

Cases (from the test file):

1. `test_id_taking_routes_are_covered` — enumerates `/v1` routes with a path
   parameter from the live OpenAPI schema and asserts the set is exactly
   `{/v1/blame/{node_id}, /v1/impact/{node_id}}`, so a newly added id-taking route
   cannot silently escape the cross-tenant matrix.
2. `test_cross_tenant_rest_ids_return_not_in_graph` — tenant B's operator token
   against tenant A's ids: blame and impact → 404 `not_in_graph`; revoke with A's
   `root_id` → 404 `not_in_graph`; gate with A's id in `relied_on` → 200 with a
   decision computed from B's graph only, no leak of A's uri or tenant id.
3. `test_cross_tenant_mcp_ids_return_not_in_graph` — the same four tools over MCP
   (`pedigree_blame`, `pedigree_impact`, `pedigree_revoke`, `pedigree_check_action`)
   with B's token and A's ids: the first three return `ok:false` with code
   `not_in_graph`; `check_action` returns `ok:true` with no leak.
4. `test_access_log_does_not_leak_other_tenant` — a cross-tenant REST blame call
   produces a `pedigree.access` line that contains neither A's secret uri nor A's
   tenant id.
5. `test_concurrent_revoke_does_not_cross_tenants` — two threads revoke concurrently
   (one per tenant) against the real DB; both end with the expected
   `revoked`/`tainted` statuses and neither graph contains the other's node ids.
6. `test_concurrent_ingest_does_not_cross_tenants` — four concurrent `record_source`
   calls (two per tenant) land in the right graphs: `+2` nodes each, no id crosses.

## Findings

None. No cross-tenant read, write, leak or unexpected 500 was observed; the
application-level isolation already in place (per-tenant graph name derived from
the bearer token, `:Node(id)` anchoring, `tenant` property checks) held under the
tested interleavings. The gate path does not 404 on an unknown id — it returns a
decision with a `not_in_graph` reason — which is the documented behaviour and is
covered as "no leak + decision from B's graph only" rather than as a 404.
