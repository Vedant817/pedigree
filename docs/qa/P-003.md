## Findings (severity)

**F1 — Low. Request-shape validation (422) precedes the demo-mode authorization check on
in-handler-guarded routes.** `POST /admin/tenants` with a malformed body and a
token-shaped header returns 422, not the expected 403, although README says
"deployment-admin HTTP routes are disabled in demo mode". Same pattern on
`POST /v1/events` without any token: `{"events":"notalist"}` → 422, while `{}` → 401.
Cause: auth is enforced inside the handler (`_require_admin`, `src/pedigree/api/routes/admin.py:11`)
after FastAPI body validation. Impact: an unauthenticated caller can distinguish
"schema-invalid" from "auth-denied" and can probe body shape; no state change is
possible, schema-valid requests are still denied (403/401), and the error body contains
no field names or validator messages, so information leakage is minimal.
Repro: `curl.exe -s -w "\nHTTP=%{http_code}\n" -X POST -H "Content-Type: application/json" -H "X-Admin-Token: <token-shaped>" -d '{"id":"qa-probe"}' http://127.0.0.1:8011/admin/tenants` → 422.

**F2 — Informational (tooling, not product code). `docker compose port db 6379` prints
`invalid IP:0` (exit 0) instead of empty output in Docker Compose v5.5.1.** The port is
genuinely unpublished (`docker inspect` → `{"6379/tcp":null}`; `ps` shows bare
`6379/tcp`), so the security requirement holds; but scripts that test "output must be
empty" for this command would misread it. `port db 9999` prints the normal
`no port 9999/tcp ...` with exit 1, confirming the message is a display quirk for
existing-but-unpublished container ports.

**F3 — Informational. Duplicate `Authorization` headers are not rejected; the first value
wins.** Valid-first → 200, wrong-first → 401 (Starlette `Headers.get` semantics). No
exploitation observed on this single-hop loopback deployment; ambiguity would only
matter behind a proxy that merges or reorders duplicate header fields.

**F4 — Cosmetic. Log/error text `module42201` lacks a space** (`scripts/runtime.py:85,86,90`,
e.g. `[runtime] database module42201 and mandatory limits verified`). It is consistent
throughout the file, so it may be intentional shorthand for "module version 42201"; noted
for the owner, no functional impact.

**F5 — Informational (positive controls).** Non-root runtime (uid 10001), `700` data dirs,
`600` credential file owned by 10001, no credential value present in container logs or
the build log, `scratch/` gitignored, repo secret scanner PASS on tracked files + history.

## Verdict

**PASS WITH CAVEATS.** Every functional acceptance criterion passed with real output:
bring-up exit 0 and healthy; uid 10001; `/readyz` true; UI 200; copied operator token
accepted; all deployment-admin attempts denied (403, except the F1 malformed-body 422,
which performs no action); DB publishes no host port; restart and `down`/`up` preserve
the graph and the byte-identical credential file; second `up` idempotent; zero credential
values in logs; repo secret scan clean. At least 10 adversarial cases were attempted.

Caveats, stated plainly: (1) one command run — the first `up -d --wait` after `down` —
failed with exit 1 because this reviewer omitted the recorded `PEDIGREE_PORT` accommodation
in a fresh shell; re-run with it passed, and the failure is environmental, not a product
defect; (2) F1 (Low) 422-before-403/401 ordering; (3) F2 Compose v5.5.1 `port` output
quirk; (4) nothing was verified on macOS, hosted deployment, or the full perf gate.

## Limitations and open questions

- macOS not run; hosted deployment not run; `make check-perf` not run; the full local
  test suite (`make test`) was out of scope for this runtime acceptance — this review is
  the README Docker Compose path only.
- The exact README commands were not executed unmodified: a distinct compose project name
  and a non-default host port were required on this shared host (recorded above).
  A host with free ports 8000/6379 would run the README literally.
- Not exercised: custom `PEDIGREE_DEMO_TENANT`, seed-failure startup path, credential
  rotation/restore procedure, hosted/MCP/CLI flows, long-running stability.
- `docker compose port db 6379` output `invalid IP:0` is recorded verbatim; the
  substantive no-host-port conclusion rests on `docker inspect` and `docker compose ps`.

## Residual risks

- F1 could matter if a future deployment relies on demo-mode admin routes being
  indistinguishable from disabled ones at the HTTP layer; fix direction (not applied):
  perform the auth check in a FastAPI dependency so it runs before body validation.
- F3 depends on proxy behaviour in deployments that terminate multiple header fields;
  fail-closed as observed (401 when the attacker-controlled value comes first).
- The review host ran several concurrent agent stacks; resource contention is possible
  but no flakiness was observed (concurrency probe 10/10 200s).
- Left behind intentionally: volumes `pedigree-p003qa_*` (for reproducibility) and the
  clone at `$env:TEMP\p003-qa-clone` containing gitignored credential copies. Remove the
  clone to delete those copies.
